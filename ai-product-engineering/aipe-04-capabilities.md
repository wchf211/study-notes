# 按需取用能力（Ch5）：RAG / Tool Calling / Agent / Fine-tuning

> 核心观点：**诊断驱动选型**，而不是默认爬梯子。没有被诊断出的故障指向它，就别加。团队最常见的浪费：缺上下文却去 fine-tuning。

## 1. 选型框架：故障选能力

- **缺信息**（模型不知道你的退款政策）→ **Retrieval**：调用时把相关文档塞进 prompt（常叫 RAG）。
- **要操作系统**（真去退款、改账户）→ **Tool calling**：让模型通过结构化调用触发你的函数/API。
- **持续性的格式/语气/风格错**（prompt 写再好也掰不过来）→ **Fine-tuning**：用自己的样本继续训练，把行为 baked in。

各治各的病，加错了 = 白花钱 + 多故障面。

## 2. Retrieval Gap：数据管道的锅，别赖模型

**Retrieval gap** = 模型答错了是因为喂给它的上下文缺/旧/错——不是它推理不行。特征：**答得自信但无来源**，或引用了错文档。

检索已接但还答错，按这个清单查：
1. 文档到底进索引了没？
2. **Chunking**（切块）太大（关键事实被埋）还是太小（上下文丢了）？
3. Embedding/query 不匹配——搜不搜得到用户那个问法？
4. 索引过期——源更新后重建过吗？
5. **top-k**（取几块）太少，模型被饿着了。

例：摘要器引用去年的退款政策——索引在政策变更后没重建。**先查喂给模型的东西，再怪模型说的话**。

## 3. Tool Calling：安全的工程问题

Tool calling = 模型输出结构化函数调用，你的代码执行。**安全是工程问题，不是 prompting 问题**：
- **最小权限**：每个 tool 只干一件窄事。反模式：一个 `update_account` 什么都能改——拆了它。
- **不可逆/大额操作要人工确认**。
- **幂等（idempotency）**：重复执行也安全——同一笔退款发两次必须不可能。
- **异常熔断**：限流、金额阈值——凌晨 3 点 1000 笔退款不该悄无声息通过。
- 执行前校验参数，每次调用都记日志。
- 金句：**把 tool 的权限收紧到"模型最离谱的误操作也死不了人"**。权限过大的 tool 配模型 = confused deputy（糊涂副手），一次误读就是财务事故。

## 4. Bounded Agentic Workflow

**Agentic workflow** = 模型循环：规划 → 调工具 → 看结果 → 定下一步，直到做完。**"Bounded"是关键词**：
- **Step budget**（如 6 步封顶）；
- 显式的 `mark_done` 动作让模型自己收尾；
- **max_steps 熔断**：超了走人工，而不是无限循环。

最大 hazard 是**误差传播**：第一步错，后面步步错——所以每步输出要校验，链条要短。
选型：单次 bounded action（一次 tool 调用，形状固定，便宜好测）vs bounded agentic（步数不定，贵、难测）——**任务真需要多步自适应才上后者**。
金句：**每个循环都要有一个"模型觉得做完了"之外的出口**。无界 agent 是 demo 惊艳、生产出事的地方。

## 5. Fine-tuning：最后才考虑

**Fine-tuning** = 用自己的样本继续训练模型，把行为 baked in。
- 上它的信号：同样格式/风格问题在**大量** case 里反复出现，prompt 和样本都救不了；想让小便宜模型在窄任务上达到大模型效果。
- 要 \~80–100+ 高质量样本（实践中常几百），**三分之二功夫花在数据清洗**。
- 别用在：缺知识（那是 retrieval 的活）、高频变的事实（得天天重训）、一次性错误。
- 它是全章**最重的**能力：数据、训练、评估、漂移后重调，全是成本。
- 口诀：**缺"知识"用 retrieval，缺"行为一致性"才考虑 fine-tuning**。这是被过度使用的工具，大多数团队最后才需要它，甚至永远不需要。

## 自测 4 问（带答案要点）
1. 三个能力各治什么病？
   → 缺信息→retrieval；要操作→tool calling；行为不一致→fine-tuning。
2. Retrieval gap 的特征和排查清单？
   → 自信但无来源/引错文档；查索引/切块/embedding/过期/top-k。
3. Tool calling 的四条安全规则？
   → 最小权限/人工确认/幂等/熔断；权限收紧到误操作也死不了人。
4. Agentic workflow 的"bounded"指什么？为什么必须有？
   → step budget + mark_done + max_steps 熔断；防无限循环和误差传播。
