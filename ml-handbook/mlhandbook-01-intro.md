# 入门（Ch1）：ML 是什么、为什么重要

> ML = 让计算机从数据里学规则，而不是人手写规则。程序见的例子越多，自己表现越好，没人逐个 case 重编程。

## 1. 术语三环

- **AI**：最外圈——机器干需要人类智能的事；
- **ML**：AI 的子集——从数据里学 pattern，不按显式指令走；
- **Deep learning**：ML 的子集——多层神经网络，从原始数据自动学特征。
- 同心圆：AI ⊃ ML ⊃ DL。

传统编程：人写规则 + 数据 → 答案。ML：数据 + 正确答案 → **机器自己学出规则（model，一个学出来的函数）** → 对没见过的 case 也能答。

**Feature（特征）**：模型用来做决定的单个可测量输入属性。例：垃圾邮件检测里，"含 lottery 这个词"、"感叹号个数"。

经典 ML 管线（课里动画图）：原始数据 → **领域专家手工提特征** → 分类器 → 输出。注意：手工提特征这步，正是 deep learning 后来自动化的。

## 2. 三种学习范式（选哪个看数据长啥样）

- **Supervised（监督）**：有标签数据（每个例子带正确答案），学输入→输出映射。再分 **regression**（预测连续数，如房价）和 **classification**（预测类别，如良性/恶性）。
- **Unsupervised（无监督）**：无标签，自己找结构——**clustering**（聚类，如客户分群）、**association mining**（关联挖掘，"买 X 的人也买 Y"）、**dimension reduction**（降维，如 PCA/t-SNE，可视化+去噪）。
- **Reinforcement（强化）**：agent 在环境里 trial-and-error，拿 reward/penalty，学出长期 reward 最大的 **policy**（策略）。例：打游戏、机器人、自动驾驶。

决策规则：有标签→监督；没标签想找结构→无监督；序列决策+反馈→强化。

## 3. ML 在数据驱动决策里的位置

数据驱动 vs 直觉驱动：前者客观有证据（但数据/分析烂则自信地错——garbage in, garbage out），后者主观易偏。

ML 解决的三难：
1. **信息过载**：量大、速度快、格式杂，人读不完；
2. **数据质量**：错数据→错决策；
3. **缺 expertise**：提 insight 要统计+算力，多数团队没有。

**但课里很诚实地列了风险**：
- **Bias/fairness**：模型学历史数据，会吸收放大人的偏见。例：用历史招聘数据训的工具系统性降分女性简历。**模型只和训练数据一样公平**。
- **Privacy/security**：要敏感个人数据；GDPR 约束。
- **黑盒**：很多模型给答案不给解释——医疗/金融里错了没法交代很危险。
- **人还是要负责**：ML 是建议不是判决。

实操：**每个模型输出都当"带 error bar 的推荐"，别当 verdict**；涉及人的预测，先审计训练数据 bias。

职业路径（课里点的名）：Data Scientist（挖 insight）、ML Engineer（建+部署模型）、CV/NLP Engineer、**MLOps Engineer**（DevOps 亲戚——管模型上线监控重训）。

## 自测 4 问（带答案要点）
1. AI/ML/DL 三环？传统编程和 ML 的输入输出区别？
   → AI⊃ML⊃DL；传统：规则+数据→答案；ML：数据+答案→规则（model）。
2. 三种范式各举一例？选型看什么？
   → 监督（垃圾邮件）、无监督（客户分群）、强化（打游戏）；看数据有没有标签/是不是序列决策。
3. Feature 是什么？为什么 deep learning 革命了它？
   → 可测量的输入属性；以前专家手工提，DL 自动学。
4. ML 的四个风险？实操铁律？
   → bias/隐私/黑盒/人负责；输出当带 error bar 的推荐。
