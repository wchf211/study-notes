## 47. Design of a Unique ID Generator（温习重点）
**需求（4 条）**：全局唯一、可扩展、高可用、64 位数字 ID（紧凑 → DB 索引更快）。

**三种方案对比**（面试标准表）：
| 方案 | 唯一 | 64 位 | 问题 |
|---|---|---|---|
| UUID | 概率唯一 | ❌（128 位） | 不可排序、太长；优点是去中心化、无需协调 |
| DB 自增 | ❌（多库漂移） | ✅ | read-modify-write 计数器是瓶颈（Spanner 单行计数器约 100 ops/sec）、单点 |
| **Range handler** | ✅ | ✅ | 专用分配器按段发号（如某台拿走 300001–400000），四项全满足 |

**记住的数字**：目标 10 亿 ID/天；2^64 ≈ 1.84×10^19，按 3650 亿/年能用约 **5050 万年**。

**顺带 trade-off**：
- ID 里加随机位可以隐藏业务量（订单量）不被外界推测。
- 单调递增 ID 会造成 DB 热点（Spanner 有此问题）。
- 纯计数器比时间戳快，但要持久化（又是瓶颈/单点）。

**面试口径**：会摆这张需求表、讲清中央计数器为什么不扩展、range allocator 怎么修好它。这是 TinyURL/Twitter 类题目的经典子问题。

## 48. Unique IDs with Causality（值得深学）
**动机**：ID 本身编码顺序/因果（如 KV 的 last-write-wins 需要时间有序 ID）。要区分"有因果"（评论后的回复）和"并发无关"（两人同时评论不同推文）。

**物理时钟方案**：
- UNIX 时间戳：简单可扩展（单机 1000 ID/秒 ≈ 8640 万/天）；同毫秒冲突 → 混入 server ID；单生成器是单点。
- **Snowflake**（Twitter）：64 位 = 1 符号位 + 41 位毫秒时间戳 + 10 位 worker + 12 位序列号 → 1024 worker × 每 worker 每毫秒 4096 个 ID；时间可排序、高可用；约 69 年耗尽（时间流逝即消耗，与用量无关）。
- 物理时钟的**根本弱点是时钟漂移**：漂移产生"未来 ID"，NTP 校准回拨会导致重复/错序。

**逻辑时钟方案**：
- **Lamport 时钟**：本地事件计数器递增；收到消息时 clock = max(本地, 收到)+1。给出与 happened-before 一致的偏序，但**不能从时间戳反推因果**。
- **Vector clock**：携带完整因果历史；向量长度 = 节点数 n，每个客户端都是节点时存储/带宽扛不住。

**TrueTime**（Google Spanner）：GPS/原子钟，返回时间**区间** [earliest, latest]，不确定度 epsilon 通常 < 7ms；区间不重叠则顺序确定。ID = 41 位 earliest + 4 位不确定度 + 10 位 worker + 8 位序列(256)。代价是昂贵 infra；区间重叠时顺序仍不确定。**五项全满足的唯一方案**（唯一/可扩展/可用/64 位/因果）。

**面试口径**：
- 严格全局有序很贵（需要分布式共识），放宽它换吞吐。
- 会对比 Snowflake vs 逻辑时钟 vs TrueTime 的五列表，点名"时钟漂移"是物理时钟的阿喀琉斯之踵。
- 背景数字：MiFID 要求交易 100 微秒 UTC 同步；Spanner 单行计数器约 100 ops/sec。

## 自测 4 问（带答案要点）
1. 设计全局唯一 ID 生成器：四项需求是什么？为什么 DB 自增主键在高并发下不行？
   → 唯一、可扩展、高可用、64 位；自增是 read-modify-write 瓶颈（Spanner 级别约 100 ops/sec）、单点、多库会漂移。
2. Snowflake 的 64 位怎么切分？它的根本弱点是什么？
   → 1+41+10+12（符号/毫秒时间戳/worker/序列号）；时钟漂移——漂移产"未来 ID"，NTP 回拨导致重复或错序。
3. Lamport 时钟 vs Vector clock：区别？为什么 vector clock 在客户端众多的系统里不实用？
   → Lamport 给出与 happened-before 一致的偏序，但不能从时间戳反推因果；vector clock 携带完整因果历史，但向量长度 O(n)，每个客户端都是节点时存储/带宽爆炸。
4. TrueTime 如何实现"全局有序"？代价是什么？
   → GPS/原子钟返回时间区间 [earliest, latest]（epsilon 通常 <7ms），区间不重叠则顺序确定；代价是昂贵 infra，且区间重叠时顺序仍不确定。
